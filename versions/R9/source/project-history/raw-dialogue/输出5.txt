# 2. 不建议把触发条件冻结成 `credits >= 2000 持续 T 秒 + utilization >= 80%`

这会在第一版引入太多参数：

- 2000 为什么？
- T 为什么？
- 80% 为什么？

目前没有必要。

我也不建议只用：

`credits >= 2000`

因为它没有表达为什么要扩产能。

第一版可以用一个更贴近经济含义、参数更少的触发规则：

```text
completedMines >= mineTarget
AND
completedLandFactories == 1
AND
noFactoryBuildPending
AND
credits >= landFactoryCost + productionReserve
```

其中：

```text
productionReserve = 当前 preferred unit 的成本
```

如果 preferred unit 是 heavyTank，就至少预留一辆 heavyTank 的资金。

语义是：

> 已经完成预定经济扩张，而且在不停止当前一厂正常生产的情况下，还有能力支付第二工厂。

这比固定 `credits=2000` 更稳定，也更符合用户刚才描述的“建厂有兵力机会成本”的实战逻辑。

# 4. 工厂位置：第一版明确采用“安全后方厂”

用户的冰岛实战经验里有一个重要提醒：

> 在前线直接造第二厂会占用 builder、消耗即时兵力价值，而且工厂本身也更容易承受高烈度骚扰。

因此 P2-B 第一版不要搞 forward factory。

优先：

> 在己方基地 / 第一工厂附近选择合法、安全的后方位置。

先验证：

> “多一个生产设施是否能消费盈余。”

不要同时引入：

> “第二厂应该盖在哪里最有战略价值。”

前线生产以后可以单独做。

# 7. “损失≈生产”现在属于一个待判定的 P3 信号

我不建议现在直接把它归到 P2-C/D。

尤其结合用户的肉眼观察：

> 主力打完以后，新生产单位会一个一个继续前往敌基地，形成添油。

这非常像：

> **出兵速率直接变成死亡速率。**

Repair 可以降低损耗，
重建可以提高恢复能力，

但它们都不能从根本上解决：

> “每造一个单位就马上送一个单位。”

所以目前先记录：

`production ≈ losses`

为一个 **P3 候选瓶颈**。

这时候主线应该暂时从 P2 转到：

而不是继续做 repair。
