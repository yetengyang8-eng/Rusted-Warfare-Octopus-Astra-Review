## 1. P2-B2 的实现语义（可直接对照代码/测试）

```text
mainline    = 任一生产者能提供的最高评分单位动作（当前 = heavyTank，score 3）
primary     = 首个能提供该动作的生产者（按原生 menu 顺序，不按 id/创建顺序）
primaryReserve = mainlineCost，仅当「主厂空闲且买不起 mainline」时持有
                 （主厂已在生产时不再空持，否则副厂会永久饿死）

主厂：mainline 买不起 → 不买便宜单位，写 production_deferred: RESERVED_FOR_PRIMARY_PRODUCTION
                       （idle 原因 BANKING_FOR_PRIMARY_UNIT；只有偏好动作真正变化才重新判断）
副厂：任何购买都需 credits - cost >= primaryReserve
       单位  → RESERVED_FOR_PRIMARY_PRODUCTION
       升级  → SECONDARY_INVESTMENT_DEFERRED
升级分类：尚无高级生产者（mainlineScore<3）或该厂即主厂 → PRIMARY_TECH_BANKING
          已有主厂时的其它厂升级 → SECONDARY_INVESTMENT_DEFERRED
```

覆盖测试（`test_battle_client.py:ProductionBudgetTests`，5 项 + 2 项迁移过来的决策测试）：

1. 主厂 T2 heavyTank(800) 买不起 + 副厂 T1 可买 c_tank(350)，credits=500 → **两厂都不下单**，主厂写 `RESERVED_FOR_PRIMARY_PRODUCTION`，副厂也被同一预留挡住，心跳 idle 原因为 `BANKING_FOR_PRIMARY_UNIT`；
2. 主厂忙（queue=1）+ 副厂空闲 → 副厂**允许**下单（不空持预留）；
3. 主厂可负担 → 直接下 `heavyTank`，无任何 defer；
4. 副厂升级（700）+ credits=900 → 归为 `SECONDARY_INVESTMENT_DEFERRED`，且**不允许**挪用主厂预留；
5. 只有 T1 厂、army≥10、升级(900) 买不起 → 归为 `PRIMARY_TECH_BANKING`（同时保留 `production_idle: BANKING_FOR_UPGRADE`）；
6. 副厂（同为 T2）在 heavyTank 买不起时买 c_tank → 仍写 `production_decision: PREFERRED_UNAFFORDABLE_FALLBACK`（说明该信号现在只在副厂出现）；
7. 主厂买得起时不得出现 fallback。

**一处主动修改需要你确认**：旧的 `test_unaffordable_preferred_unit_is_recorded`（单厂 fallback）在新规则下**必然失效**——它断言的正是 §5 禁止的行为。我把该用例删除并把 fallback 断言迁到副厂场景（第 6 项），没有保留「主厂也可以 fallback」的任何路径。这是行为改变带来的测试语义更新，不是放宽断言。
