## 2. §5：capability 解析缺陷——原因与修正（我此前的表格结论作废）

**你指出的两处矛盾都成立，原因如下：**

### 2.1 `aircraft=NONE` 与表内 `gunShip` 并存 → 我的脚本 bug

`raw_flag_table.py` 里的探针集合写成 `{'lightGunship','gunship','helicopter','c_interceptor','interceptor'}`，而 `AIRCRAFT` 判定用了 `t in AIRCRAFT`，其中 **`gunShip` 的大小写与集合内的 `gunship` 不匹配**，同时旧代码构造集合时嵌套了一层（`frozenset` 被放进列表），于是 `gunShip` 明明在表里，标签却打 `aircraft=NONE`。**这是脚本缺陷，不是报告缺陷。**

### 2.2 《对话19》里 `am.cI` 的取值与 raw table 相反 → 我手工对错了列

旧脚本用固定宽度打印、我在写交接时按肉眼对齐读列，**整体错位了一列**（我读到的是相邻字段的值）。同一张表里 `c_tank/heavyTank` 的真实 `am.cI` 是 **1**，`gunShip/heavyHoverTank` 也是 **1**，所以"0 vs 1 可以区分空/地"的结论**完全不成立**，我撤回。

### 2.3 修正（已提交，仍不改 Agent 行为）

1. `AIRCRAFT` 改为扁平 `frozenset`（含 `gunShip`/`c_helicopter`/`heavyInterceptor`）；
2. 表格改为**先解析表头、再按字段名取值**（`booleans[field]`），从结构上杜绝列错位；
3. `aircraft=` 标签与表格用**同一份类型集合**生成。

### 2.4 修正后的原始值（`助手交接\evidence\raw_flag_table_cap40.txt`）
