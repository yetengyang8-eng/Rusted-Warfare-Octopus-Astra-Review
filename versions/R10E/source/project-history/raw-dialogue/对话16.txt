## 0. 本轮：执行《输出15》最小修正（唯一改动）+ 全回归 + 安装

范围严格按《输出15》§8：**只做 secondary investment 的 defer→cheap fallback 这一处**，没有顺手施工任何 backlog（mineTarget=3 / mobileUnitHardCap=32 / squad/targeting / defence / sea / unit scoring 全部未动）。

改动落在 `BattleClient.produce()` 的空闲工厂分支，**插入**在原 primary 规则之前：

1. 非主厂、且当前 chosen 不是 upgrade 时，先取 `upgradeCandidate(f)`（该厂菜单里的 upgrade 动作）；
2. 计算 `payable = credits - upgradeCost >= primaryReserve`；
3. 若 `!payable && (army>=10 || upgradeCost>credits)`：
   - 先记 `production_deferred{reservedFor=SECONDARY_INVESTMENT, reason=SECONDARY_INVESTMENT_DEFERRED}`（即 §2 的"机会性盈余投资"语义）；
   - **然后继续检查 lower-cost legal action**：若 `credits - chosenCost >= primaryReserve` 成立 → 记新事件 `SECONDARY_INVESTMENT_FALLBACK` 并下单；不成立才 `BANKING_FOR_SECONDARY_UPGRADE` 并 `continue`；
4. §4 两条红线**未触碰**：`PRIMARY_TECH_BANKING` 分支（`enablement = mainlineScore<3 || primary`）与 `RESERVED_FOR_PRIMARY_PRODUCTION` 分支保持原样，主厂仍然不 cheap fallback；
5. §5 未改评分：`unitScore` 仍是 1/3/5。

**新事件 schema（§6 建议的明确日志）**：

```json
{"event":"SECONDARY_INVESTMENT_FALLBACK","data":{"factoryId":9,"factoryTier":1,"credits":1400.0,
 "deferredUpgradeCost":2000,"chosenUnit":"c_tank","chosenCost":350,"primaryReserve":800,
 "reason":"SECONDARY_INVESTMENT_FALLBACK","gameTimeMs":4000}}
```
