## Q1：L0 为什么把 `cu` 变成 -1？——**已定位到具体的引擎方法，不是缓存语义**

阶段二分（`safe_path_purity_probe.txt`，逐阶段各发一次请求并读 `cu/cv`）：

```text
baseline                    attacker cu/cv=210/210  target cu/cv=4000/4000
after stages=resolve        210/210                 4000/4000
after stages=type           210/210                 4000/4000
after stages=building       210/210                 4000/4000
after stages=floats         210/210                 4000/4000
after stages=radius         -1/210      <== 第一次出现 -1
after stages=dump           -1/210
after full default request  -1/210                  -1/4000   <== 两个单位都被写
```

`stages=radius` 那一行执行的是**我自己的代码**：

```java
rawInvoke(rawMethod(am.getClass(),"cj"),attacker)     // 我以为是"读碰撞半径字段"
```

而 `am` 上同时存在 **字段 `public float cj`** 和 **方法 `public void cj()`**。`rawMethod(am.class,"cj")` 按名字解析到的是**方法**，其完整字节码是：

```text
public strictfp void cj();
   0: aload_0
   1: ldc   -1.0f
   3: putfield  Field cu:F
   6: return
```

**`am.cj()` 的全部内容就是 `cu = -1`**。而 `cu` 正是桥接 `observe()` 导出的 `hp`（`RuntimeBridge.java:351-352`）。所以：

- **不是** Fixture normalization，**不是** snapshot/reporting artifact；
- 是**真实的字段 mutation**，由我的诊断调用了一个**故意的置死方法**。

直接调用证据（`factory_delayed_effect_probe.txt`）：

```text
after DIRECT field read  u.cj=11.0          cu=210
after reflective Field.get(cj)=11.0         cu=210     ← 字段读无害
after Class.getMethod("cj") -> public void cj()   cu=210
after m.invoke(u)                            cu=-1     ← 方法调用置死
u.cj() #1                                    cu=-1
u.cj() #2 （幂等）                            cu=-1
```

**结论**：`-1` 是**真实 mutation**。A-only 在过去**不等于 live-safe**——你的判断成立。

## Q2：默认 request path 是否真的没有任何 engine method call？——**不是；我上一版的表述不实，已更正**

我之前写"Field.get only / METHOD CALLS = none"**只对字段收集器成立，对整条请求路径不成立**。完整路径（源码行号已核）实际调用：

| 调用 | 位置 | 用途 | 字节码审计 |
| --- | --- | --- | --- |
| `u.cW()` | `own()` / `anyUnit()` 的存活过滤 | 建造完成判定 | 无直接写入 |
| `attacker.r()` / `.i()` | payload `attackerType` | 类型名 | 无直接写入 |
| `target.r()` / `.i()` | payload `targetType` | 类型名 | 无直接写入 |
| `target.bI()` | payload `targetBuilding` | 建筑判定 | 无直接写入 |
| ~~`am.cj()`~~ | ~~`collisionRadiusRaw`~~ | ~~"读半径"~~ | **void mutator：写 `cu = -1`（已移除）** |

所以正确口径是：

```text
CURRENT_SAFE_PATH_ENGINE_METHOD_CALLS = { cW(), r(), i(), bI() }        （均为非 void 查询）
CURRENT_SAFE_PATH_FIELD_READS         = reflected Field.get on cj/eo/ep/eh/bX/cu/cv + declared floats
CURRENT_SAFE_PATH_REMOVED             = am.cj()  (was a void state mutator)
```

**修复**（本轮）：

1. `collisionRadiusRaw` 改为**字段读取**（`Field.get`），payload 内新增 `"readVia":"Field.get"` 自证；
2. 新增**反射纯度护栏** `isPureQuery(Method)`：`rawInvoke()` **拒绝**任何 `void` 返回的方法，以及已知工厂访问器（当前为 `ar.a()`），并把跳过计数写进 payload（`reflectionGuards.voidMethodsSkipped / factoryAccessorsSkipped`）。这样"按名字调用"不再可能命中置死/工厂方法。
