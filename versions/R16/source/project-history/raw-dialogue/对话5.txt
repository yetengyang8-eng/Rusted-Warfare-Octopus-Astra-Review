## 2. 但经济没有变成兵力，而是变成了「囤钱」

| 指标 | 基线 #2（1 矿） | 基线 #3（1 矿） | **本局 #4（3 矿）** |
| --- | --- | --- | --- |
| 矿数 | 1 | 1 | **3**（81/117/183s） |
| 生产 / 损失 | 83 / 84 | 83 / 84 | **55 / 58** |
| 军队 中位 / 最大 | 5 / 13 | 5 / 13 | **4 / 8** |
| credits 中位 / 最大 | 561 / 2690 | 561 / 2690 | **4,283 / 9,670** |
| 主产兵种 | c_tank | c_tank | **heavyTank 54 辆**（c_tank 仅 1 辆） |
| 单厂队列非空比例 | 90% | — | **93%** |
| 原生结算 | ONGOING | ONGOING | ONGOING（限时） |

**读法**：多出的收入**没有**变成更大的军队（中位反而从 5 降到 4），而是变成了**闲置资金**（中位 4,283，最高 9,670）。同时兵种从 c_tank 换成了 heavyTank——这正是用户观察到的「高经济让脚本开始自动续重坦」（`produce()` 给 heavyTank 打分 3 高于 c_tank 的 1，一旦买得起就优先重坦）。

**瓶颈从「钱」转移到了「单厂产能」**，可以算得很清楚：

- 3 矿收入约 **57 资金/游戏秒**（900 秒内支出 54×800 = 43,200，同时净累积约 8,000）；
- 单厂 900 秒只能吃下 **54 辆 heavyTank ≈ 48 资金/游戏秒**；
- 差额约 9/s 无处可去 → 累积成 9,670。

也就是说：**即使多了两座矿，一座工厂也无法把收入转成战斗力。** 你的 P2-B 三个触发条件在本局**同时成立**：第二矿稳定工作 ✓、单厂长期高利用（93%）✓、资源可持续盈余 ✓。

## 4. 请你裁决

1. **P2-B 现在做吗？触发规则怎么定？** 我的提议是：`矿数达到 mineTarget` **且** `credits ≥ 阈值（例如 2000）持续 T 游戏秒` **且** `工厂队列非空比例 ≥ X%（例如 80%）` → 建第二座工厂。要不要现在把这个规则冻结成具体数字，还是先只做「credits 高于阈值就建第二厂」这一条最小规则？我倾向后者（更少参数、更容易归因），但想听你的意见。
2. **P2-B 是否要同时引入「花掉盈余」的规则？** 我担心的是：即便建了第二厂，若 `mobileUnitHardCap=32` 与 heavyTank 的成本组合仍然让支出上限低于收入，钱还是囤。可选：(a) 只加第二厂（单一变量）；(b) 第二厂 + 提高兵力上限；(c) 第二厂 + 允许升级到更贵的兵种。按你「一次只改一个主要变量」的原则我倾向 (a)，但那样下一局可能仍是「两厂一起囤钱」。你会怎么切？
3. **损耗平衡是不是下一个真正的靶子？** 四局都是损失≈补充。它属于 P2-C/D（重建、修理）还是 P3（集结与攻击阈值）？如果目标是先让军队规模真的涨起来，你认为哪一项在前才能保持因果清晰？
4. **要不要补一个显式的工厂饱和/资金盈余诊断？** 例如在工厂队列持续非空且 credits 超过阈值时，定期记一条 `production_surplus`（含 credits、queue 状态、单位成本），这样「钱花不出去」在报告里直接可见，不必靠曲线反推。这是纯诊断，不改行为。
