## 3. 残留风险（我确认过的，不含已排除项）

1. **端口预留存在 TOCTOU 窗口**（真实但低）：`reserve_port()` 先 `bind(('127.0.0.1',0))` 取端口再关闭，
   引擎随后才绑定。批内靠 `self.ports` 集合保证 A/B 不同，但**外部进程**理论上可在这毫秒级窗口里抢占。
   影响：单机安静环境下没遇到过；若要跑无人值守长批次，值得加一次「引擎绑定成功后再核对端口归属」的检查
   （现有 `verify_owner` 已核对 health 报告的 port，等于已经事后验证——所以只是窗口期风险，不是静默错误）。
2. **强杀 Python 编排器会漏掉两个引擎**（Codex 自述，**我已实测确认**，不是推测）：
   探针 `_analysis\kill_orchestrator_probe.ps1`（结果 JSON 在 `%TEMP%\kill_orch_result.json`）：
   启动双实例 suite → 屏障后两引擎存活、两端口 LISTEN、java 总数 4（2 引擎 + 2 客户端）→
   `Stop-Process -Force` 杀掉编排器 → **+1 秒** 客户端随之消失（java 4→2），但
   **两个引擎在 +1s / +10s / +20s 三个采样点都仍存活、仍 LISTEN、CPU 时间持续增长**
   （4.8→5.1→5.2→6.5 秒，说明在继续推进模拟，不是僵尸）。按 PID 清理后 java=0、端口全部释放。
   影响：无人值守批量跑时，上层若用超时强杀编排器，会留下两个占端口的引擎，直到各自的
   `--max-wall-seconds` 到期。**建议（下一轮可选，最小改动）**：编排器启动时把
   「本批 PID + 端口 + 工作目录」写进 `live-claims.json` 并随进度更新，另加 `--reap <run 目录>`
   只清理清单里的 PID 并复核端口释放——既是崩溃恢复手段，也让「异常退出自行清理」这条验收可复核。
3. **真正同局双 Agent 的 self-play 不在本能力范围内**：`HeadlessRunner` 明确
   `if(engine.bX.B || engine.cb.j()) throw "Only local matches are supported"`，
   且其 CLI 只有 `--map/--port/--speed/--max-wall-seconds/--frames/--difficulty`。
   这是**桥接/大厅层**的限制，不是 runner 的限制（详见 §5）。
4. **条件可复现性未闭环**：引擎有 `seed`（`runtime.json` 里 `"seed":…, "seedReproducibilityVerified": false`），
   但 CLI 没有 `--seed`，也没有验证同一 seed 是否复现同一局面。做参数 A/B 前需要先解决（见 §5）。

已排除：Codex 提到的 `engine-process.json` 里中文路径「带替换字符」——**我这次跑出来的两份文件
U+FFFD = 0**，`command[0]` 是完整的 `G:\deepseek 工作台\…\jvm64\bin\java.exe`。
所以那是它沙箱的写读编码问题，不是产物缺陷；宿主上该字段可逐字节复原。

## 5. 任务 4：下一步建议（暂不施工）

**建议下一项：`固定条件 A/B 对比能力 v0`**（而不是直接进 self-play 设计阶段）。理由与最小接口：

现在有的：两实例完全隔离、可并发跑、退出码与证据自证完备。
**进入「限制规则双 Agent / self-play v0」还差三件最小接口**：

1. **每实例可注入不同规则 profile**（今天所有旋钮都是 `-Drwagent.*` 系统属性，只能整批一致）。
   最小做法：支持 `--profile <json>` 或 `-Drwagent.profile=A|B`，profile 只覆盖既有旋钮，不新增策略。
2. **条件固定**：固定地图/难度已有（`--map/--difficulty`）；缺 **seed 控制**与「同 seed 是否复现」的验证
   （引擎自报 `seedReproducibilityVerified: false`）。**若 seed 不可设**（需要写引擎内部状态，
   触及 Diagnostic Lab 禁区），替代方案是先做「重复 N 局 + 配对同条件 + 报方差」，
   并在结论里明确「同条件但不同随机」——这一步需要裁决，不要先动引擎。
3. **跨批聚合**：现在 `batch.json` 是单批的；参数比较需要一个只读聚合器
   （按 profile 汇总胜率/经济曲线/损失/关键事件计数，按批号与候选 contentDigest 归档）。

**为什么不是直接上同局 self-play**：同局双 Agent 需要大厅/桥接层支持「两个非 AI 玩家、各自一个客户端」，
而当前 headless 路径显式只允许本地单玩家。这是一个**独立的大工程**（与 P0/Lab 边界相邻），
不适合作为下一小步。而上面 1–3 三件小事做完，就能先用「两实例 + 不同 profile + 固定条件 + 跨批聚合」
得到**统计可比的 A/B**，这正是路线里「批量自对弈 + 参数比较/自动调参」的前置，
且不需要碰任何策略语义。
