## 3. §6：`(ao,float×4,int×3)` 三个 int 参数——字节码级结论

完整追踪：`助手交接\evidence\engine_semantics_trace.md`。摘要：

**调用链**：`aq.a(ao,FFFFIII)Z` → 直接转发 `aq.b(ao,FFFFIII)Z` → 把世界坐标换算成地图格（`b.a(FF)` → `b.T/b.U`）→ 调私有 `a(ao,IIIIIII)Point`。

**私有方法内部**（判定为"沿直线逐格步进"）：

| 参数 | 含义 | 依据 |
| --- | --- | --- |
| `int1` | **预算 / 模式阈值** | 与累计移动代价比较，达到即返回当前格；在代价模式下也用 `k.l.b(grid,tx,ty)==-1` 立即返回 |
| `int2` | **代价阈值**（0 = 关闭该早退分支） | `if (int2 != 0) { c = k.l.c(grid,tx,ty); if (c < int2) return 当前格; }` |
| `int3` | **剩余搜索步数** | 循环开头 `if (int3 > 0) int3--;`，每步递减 |

**返回值语义**：`null` = 一直走到终点都没有触发任何早退；非 `null` = 在某个格停下（并把该格写进返回的 `Point`）。所以 `aq.b(...)` 里 `path==null → return true` 意味着"**直线畅通到达**"，而返回非 null 表示"**在某处被挡住 / 触发阈值**"。

**引擎自己的取值（关键收获）**：`com.corrodinggames.rts.game.units.y` 的 `a(float,float,int,boolean,boolean)` 里：

```text
budget = 80                (bipush 80)
mode   = 0；若第 4 个 boolean 参数为真 → 3
steps  = 1                 (iconst_1)
→ aq.a(this.h(), this.eo, this.ep, tx, ty, budget, mode, steps)   // (80, 0或3, 1)
```

返回值 true 会立刻进入"移动/站位"分支（复位 `u/aw/au`，再做坐标换算与距离计算）——这就是引擎自己"走向目标 / 找射击位"用的原语。**因此 `(0,0,0)` 是我们之前的猜测**，已按你的要求在端点里标注：

```json
{"signature":"a(ao,float,float,float,float,int,int,int)->boolean",
 "argsUsed":["movementClass","fromX","fromY","toX","toY",0,0,0],
 "argSemantics":"ARG_SEMANTICS_UNRESOLVED",
 "rawResult":"…",
 "enginePatternArgs":[80,0,1],
 "enginePatternRawResult":"…"}
```

—— 每次调用同时给出"我们的猜测"和"引擎自己的参数组"两组 raw 结果，便于实机直接对照。

## 4. §8/§9：射程与几何的调用链调查（部分解决）

### 4.1 几何半径：**已找到，且有公式**

`com.corrodinggames.rts.game.units.am.t(am)` 的字节码：

```text
d2 = f.a(this.eo, this.ep, other.eo, other.ep)   // 距离平方
r  = this.cj + other.cj                          // 双方半径之和
return d2 < r*r
```

→ **`cj` 就是单位/建筑的半径字段**，邻接/碰撞判定用的就是它。这比"字段名含 radius"的启发式可靠得多；端点里的 `targetRadiusRaw` 会在实机里与 `cj` 对照（同一个值应出现两次才算锚定）。

- 下一步实机计划（只读）：
  1. 对已知兵种（`c_tank` / `heavyTank` / `c_artillery` / `c_antiAirTurret`）dump **全部 float 字段的原始值**；
