## 1. 实现（全部在编排器内，最小改动）

- **`live-claims.json`（本批进程登记簿）**：`class LiveClaims`，编排器启动即写、**进程创建时登记、退出时更新**
  （原子写）。每条含 `role`（orchestrator/engine/client）、`pid`、`port`、`workDirectory`、`episode`、
  `sessionId`、`commandMarker`、`state`（RUNNING → EXITED/GONE/REAPED）、时间戳与 `exitCode`。
  批次收尾做一次对账：**只有查得到进程表时才判断**；查不到就保持 RUNNING（不把"查不到"当成"已退出"，
  否则会掩盖真实泄漏）。若该 PID 已属于别的进程（PID 复用）或确实消失，则标记退出。
- **`--reap <run 目录>`**：只读登记簿，**逐条复核身份后才杀**——
  engine 需命令行含 `io.rwagent.headless.HeadlessRunner` 且含 `--port <登记端口>` 且该端口的 LISTEN 拥有者是本 PID；
  client 需含 `io.rwagent.client.` 且含 `-Drwagent.port=<登记端口>`；**orchestrator 角色一律拒绝**
  （PID 被复用也不会误当成编排器）。用 `taskkill /PID <pid> /F`（不带 `/T`）。之后复核 PID 消失与端口释放，
  **只有"确实杀过"的条目才计入失败**（身份不符而跳过的进程不算失败）。幂等：状态写回登记簿，二次执行 `killed=0` 仍 PASS。
  产物 `reap-report.json`（`killed` / `skipped` / `verified` / `status`）。
- `--game-dir` 改为可选（`--reap` 不需要游戏目录）；不带 `--reap` 时行为与之前完全一致。

## 4. 剩余风险（诚实清单）

1. **引擎刚 Popen 就被杀的瞬间**可能少写一条记录（写入本身原子）：最坏是漏清理**一个**进程，**不会误杀**；
   reap 报告会列出端口未释放，可再次复查。
2. **`--reap` 依赖 Windows PowerShell 查询**（`Get-CimInstance` / `Get-NetTCPConnection`）：查不到身份时
   **一律跳过而不杀**——这是"绝不误杀"的取舍，代价是那种环境下 reap 不生效（日志可见）。
3. 端口 TOCTOU 窗口（上一轮已登记，本轮未处理）。
4. reap **不做跨批次清理**：一次只认一个 run 目录的登记簿（有意为之，避免越权）。
