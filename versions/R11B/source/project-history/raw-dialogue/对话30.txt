## 2. 遇到的三个问题（都已修，但请你复核）

### 2.1 Astra 的口径落差（属实）

我写的契约是 "owner + name + descriptor 匹配"，实现里只按 `owner#name` 匹配、descriptor 仅作说明文字，而且沿父类链无限制匹配。现在：白名单 = `owner#name -> {真实参数化 descriptor -> 用途}`，`isAllowlisted()` 精确比较参数类型+返回类型，父类链匹配**只认本身已在白名单里的 owner**，被拒绝的调用计入 `reflectionGuards.notAllowedSkipped` 并记录签名。

### 2.2 我自己在第 1 版修复里制造的回归（**本轮最重要的发现**）

第 1 版按"宁可少放行"把父类链匹配整条删掉，结果 movement-class 路径被**静默关闭**：

```text
attacker.getClass().getMethod("h")  declaringClass = com.corrodinggames.rts.game.units.e.j
descriptor = ([])->com.corrodinggames.rts.game.units.ao
第 1 版：attackerMovementClass = null  , source = FIELD_SCAN_FALLBACK
第 2 版：attackerMovementClass = "LAND", source = y.h() via y#h
```

也就是说：`am#h` 这条白名单条目永远不会命中具体子类的声明，删掉父类链匹配不是"更安全"，而是功能回归。**请复核"父类链只认已审计 owner"是否满足你要求的安全边界**——我的理解是可达范围仍被限制在已审计 owner 的签名集合内，不引入任何新类。

新增回归用例（`ReachabilityHarness`）：遍历真实白名单 × 真实 `getDeclaredMethods()`，4 条已审计签名全部放行、`every non-audited same-name overload is refused (8/8)`；具名反向对照 `am#cj`（void，方法体 `cu=-1`）、`ar#a`（工厂访问器）、`k.l#b`（未审计 owner）全部被拒。

### 2.3 另外两个缺陷

1. **我的诊断 payload 自相矛盾**：`notAllowedSkipped` 原本只在 `stages=allowlist` 出现；补进主 payload 后我发现它**序列化在同一响应内那些拒绝调用之前**——自报 0，但同一个 body 里写着 62 处 `SKIPPED_NOT_ALLOWLISTED`。已把 guard 汇总移到 payload 末尾，并加用例断言"计数覆盖本响应内全部拒绝"。
2. **证据增量工具链出错**：`_analysis/evidence_index.py` 解析自己写出的索引时没去掉反引号，sha 永不相等 → 所有历史证据被标成 UPDATED → delta manifest 一次要求上传 **48 个文件**，正是"手工挑文件出错"这个协议要防的事。修复后本轮 SEND = **4 个文件**。这条属于工具链，请一并确认。
