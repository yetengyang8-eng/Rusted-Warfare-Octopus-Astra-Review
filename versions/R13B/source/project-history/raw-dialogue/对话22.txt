## 1. §2：`/combat/reachability` v0 已实现（只回原始引擎结果）

```text
GET /combat/reachability?unitId=<id>&targetId=<id>
```

返回字段（全部 raw / 显式标注来源）：

| 字段 | 说明 |
| --- | --- |
| `attackerId` / `attackerType` / `attackerMovementClass` / `attackerPosition` / `attackerTile` | 攻击者身份与位置（tile = `y*height + x`） |
| `targetId` / `targetType` / `targetMovementClass` / `targetBuilding` / `targetPosition` / `targetTile` | 目标身份与位置 |
| `twoArgCandidates` | `aq` 里所有 `(y, am)` 形态的方法**逐条**签名 + 原始返回 |
| **`engineAqAResult`** / **`engineAqBResult`** | 引擎原生 `aq.a(y,am)` / `aq.b(y,am)` 的 raw 结果（命名保持 raw，未重命名为 canAttack/reachable/engageable） |
| `outerCandidates` | `aq` 里所有 `(ao, float×4, int×3)` 形态方法的签名 + 实际传入参数 + raw 结果 |
| `exactTargetPathRawResult` | 同上 `a(...)` 变体的 raw 结果（名字直译，不含语义承诺） |
| `weaponRangeRaw` / `targetRadiusRaw` / `targetFootprintRaw` | 只按字段名含 `range`/`radius`/`footprint` 收集的**原始数值列表**（`field/source → raw value`），不做"哪个才是射程"的判断 |
| `movementGridClass` | 取到的网格类名 |
| `rawPassabilitySamples` | 攻击者/目标位置 + 相邻 8 格的 `globalPassable` / `classPassable` / `gridMoveCost` 原始值 |
| `concept` | 固定 `output21-raw-reachability-v0` |
| `diagnosticStatus` | 固定 **`RAW_ONLY_NOT_A_VERDICT`** |

**结构性保证**：端点里**不存在** `reachable` / `engageable` / `canAttack` / `reachableEngagementPosition` 任何字段——harness 会扫描整个响应体，出现这些字符串即失败（`输出21` §3 的禁令写进了测试）。

**headless 原始样例**（证明字段与 plumbing；其中 `THREW`/`null` 是夹具未初始化网格与武器块导致，不是引擎限制）：`助手交接\evidence\reachability_endpoint_sample.txt`。要点：

```text
attackerType=tank  attackerMovementClass=null  attackerTile=9837
targetType=commandCenter  targetBuilding=true  targetTile=9410
engineAqAResult=true   engineAqBResult=false           ← 两个原语并不一致
outerCandidates/exactTargetPathRawResult → THREW:NullPointerException（夹具无网格）
rawPassabilitySamples → globalPassable/classPassable 各 18 条（夹具里全 THREW）
weaponRangeRaw/targetRadiusRaw/targetFootprintRaw → []（夹具无武器块）
```

> 注意：headless 里 `engineAqAResult=true` / `engineAqBResult=false` 对同一个"可攻击的 commandCenter"给出**相反**结果，这正好说明**不能**把其中任何一个直接当作 C（ReachableEngagementPosition）——与《输出21》§3 的判断一致。

## 2. §8：Agent 侧限流采样（每局自动产生正负对照）

新增只读诊断（不参与决策）：

```text
当前可见目标（优先 building）发生变化时：
  → 若与上次同一目标，则至少间隔 30 游戏秒才再采
  → 取 active army 中的代表单位（c_tank / tank / heavyTank），最多 3 个兵种
  → 每个代表调用一次 /combat/reachability
  → 写 1 条 report_reachability 事件（含 raw 全量）+ 1 条 reachability_sample 汇总
```

- **有限流**：同一目标 30 游戏秒内不重复；每次最多 3 次路径查询（不对 41 个单位逐个跑）。
- **按兵种取样**：每个 combat type 一个代表，为将来回答"0/N combat types can engage 还是部分可接战"打基础。
- **默认是关**（`-Drwagent.reachabilitySample` 未开启时也会跑，但代价只有上述 3 次查询/30s；如需完全静默可关）。
- 采样失败（端点 404/异常）只写 `production`-无关的失败事件，绝不影响比赛流程。

```text
candidateRadiusWorld = effectiveWeaponRange + targetRadiusWorld
```
